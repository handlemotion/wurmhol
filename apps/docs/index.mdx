Wurmhol gives your coding agent's dev server a private HTTPS link that you open in your own browser, on your phone or your laptop. Only people in your org get in.

```bash
npx wurmhol 8787
```

It prints a link like `https://k3x9p2m7qa.wurmhol.dev` and returns.

## Why it exists

Everyone is building agent orchestrators and cloud sandboxes right now, and most of them have no way to show you what the agent built. The agent spins up a web app you can't open. Sandboxes like Claude Code on the web only reach the internet through an HTTPS proxy on port 443, with no DNS and no other ports, so ngrok and Cloudflare Tunnel can't get out. We tried them from a Claude Code cloud session, quick tunnels and ngrok never connected, and the ones that did needed a login every session or an app on every viewer's device.

Wurmhol needs one outbound WebSocket on 443, the one thing every sandbox allows, and it goes through the proxy like any other request.

It also means you don't wait on preview builds. A pipe is the dev server itself, so every save shows up on refresh, hot reload included. We review these docs the same way.

## Who can open a pipe

Only signed-in members of the org that owns the token. Everyone else lands on the sign-in page and never sees your app, there are no public links. Every open pipe also shows up on your org's [wall](/glossary#wall).
