| Command                         | Does                                                                                |
| ------------------------------- | ----------------------------------------------------------------------------------- |
| `wurmhol <port>`                | Open a pipe to a port, print its link and return                                    |
| `wurmhol ls`                    | List open pipes and when each one ends                                              |
| `wurmhol stop <port\|id\|name>` | End one, or every one with `--all`                                                  |
| `wurmhol logs <port\|id\|name>` | Recent requests and connection events; `--follow`, `--json`                         |
| `wurmhol init`                  | Tell this repo's agents how to share, `--skill` adds the skill                      |
| `wurmhol host`                  | Connect this computer, to open pipes from Create pipe; `--install` keeps it running |
| `wurmhol doctor`                | Check the token, proxy, allowed hosts and, with `--port`, the dev server            |
| `wurmhol login`                 | Approve this computer in the browser and save a token                               |
| `wurmhol logout`                | Delete the saved token                                                              |
| `wurmhol mcp`                   | Run the [MCP server](/mcp) on stdio                                                 |

## Open pipes from the browser

`npx wurmhol host` keeps this computer connected to your wall. In Create pipe, **Create from this
computer** gives you the command to run, with a one-time setup code that logs this computer in as
you, then lists the web servers running on it, by port and page title; pick one and its pipe opens.
Debuggers such as Node's inspector are left out; set `WURMHOL_HOST_IGNORE` to leave out other ports.
Run without `--code` and with no token yet, it logs in first: approve it at the link it prints. Only
you see your computers, and only ports they report can be opened. Pipes it opens keep running when
you stop it; end them with `wurmhol stop` or Terminate on the wall.

### Keep it running

`wurmhol host --install` starts it now and at every login, and restarts it if it stops. It needs
Wurmhol installed, not run through npx, so the service finds it after a restart:

```bash
npm install -g wurmhol
wurmhol host --install
```

It uses the token `wurmhol login` saved, and logs in first if there is none. Its output goes to
`~/.wurmhol/logs/host.log`. `wurmhol host --uninstall` removes it; pipes it opened keep running.

On macOS it is a launch agent, `~/Library/LaunchAgents/com.wurmhol.host.plist`. On Linux it is
a systemd user service, `wurmhol-host` (`systemctl --user status wurmhol-host`); without systemd,
keep `wurmhol host` open in a terminal. Windows is not supported yet. If you switch Node versions
and remove the old one, run `wurmhol host --install` again.

## Doctor

`wurmhol doctor --port 5173` checks what a pipe needs and prints one line each, `ok` or the fix:
the token, `HTTPS_PROXY` and `NODE_EXTRA_CA_CERTS`, whether the network lets the CLI reach its host
(`api.wurmhol.com`) and the pipe domain (`*.wurmhol.dev`), and whether the port answers HTTP on
`127.0.0.1` or `::1`. It exits 1 when any check fails; `--json` prints
`{checks: [{name, ok, detail, fix}]}`. `wurmhol init` and `wurmhol login` name the hosts to
allowlist first, for a sandbox with Limited network access.

## Logs

`wurmhol logs 5173` prints a pipe's last 50 lines: each request your viewers made, as method, path,
status and time taken, and when the pipe connected or dropped. `--follow` keeps printing new ones.
Query values, bodies, headers and cookies are never written; `/cb?code=abc` is logged as
`/cb?code=`. The log stays on this computer, in `~/.wurmhol/logs`, at most about 2 MB per pipe,
and Wurmhol's servers keep none of it.

## Flags

| Flag                     | Does                                                                        |
| ------------------------ | --------------------------------------------------------------------------- |
| `--ttl 8h`               | How long the pipe lasts, like `90m` or `8h`. 4 hours by default, 12 at most |
| `--name my-app`          | Open it at `https://my-app.wurmhol.dev`, the same URL every time            |
| `--only a@x.com,b@y.com` | Only these org members can open it                                          |
| `--note "text"`          | A line of text on the pipe's card, up to 280 characters                     |
| `--link <url>`           | A link on the pipe's card                                                   |
| `--path /checkout`       | Print the link opened at this page; `pageUrl` in `--json`                   |
| `--json`                 | Print JSON, `{url, port, id, endsAt}` for a pipe                            |

## Variables

| Variable              | Does                                                     |
| --------------------- | -------------------------------------------------------- |
| `WURMHOL_TOKEN`       | Your org's token. Wins over one saved by `wurmhol login` |
| `WURMHOL_URL`         | Your own install, if you [self-host](/self-hosting)      |
| `WURMHOL_HOST_IGNORE` | Ports `wurmhol host` never lists, like `9229,5555`       |
| `HTTPS_PROXY`         | The proxy to go through                                  |
| `NODE_EXTRA_CA_CERTS` | Your proxy's certificate                                 |

Run the same `wurmhol <port>` again and it prints the pipe that is already open instead of opening
a second one. A different `--name`, `--only`, `--link` or `--note`, or any `--ttl`, opens a new
pipe; for a new URL with the same flags, `wurmhol stop <port>` first.

When something fails, the error is one line with what to do about it. Node 22 or later.
