## Sign-in

Passkeys work with no setup. For Google or GitHub, create OAuth clients with these callbacks and set `GOOGLE_CLIENT_ID` or `GITHUB_CLIENT_ID`, plus the matching `_SECRET` as a secret.

- Google, `https://dirt.example.com/api/auth/callback/google`
- GitHub, `https://dirt.example.com/api/auth/callback/github`

Magic links go out through Cloudflare Email Service. Onboard your domain under Email Service, Email Sending, and set `MAIL_FROM`, like `sign-in@example.com`. There's no API key, the `EMAIL` binding in `wrangler.jsonc` is the credential. Without `MAIL_FROM`, sign in with OAuth and add a passkey.

## Billing

Leave `STRIPE_SECRET_KEY` empty and every org opens pipes without a plan. To charge, set up Stripe like this.

1. One product with a yearly price and, if you want, a monthly one. Their ids go in `STRIPE_PRICE_YEARLY` and `STRIPE_PRICE_MONTHLY`.
2. A webhook to `https://dirt.example.com/api/auth/stripe/webhook` for `checkout.session.completed` and `customer.subscription.created`, `.updated` and `.deleted`, with its signing secret as `STRIPE_WEBHOOK_SECRET`.
3. The customer portal turned on in Stripe's settings.

There's no trial, an org subscribes before its first pipe.

## Preview links on pull requests

Optional. With a GitHub App set up, every open pipe shows up on the open pull request of its branch as a `wurmhol-preview` deployment, with a button to the pipe. Leave `GITHUB_APP_ID` empty and nothing talks to GitHub.

1. Create a GitHub App with the callback URL `https://dirt.example.com/api/github/callback`, the setup URL `https://dirt.example.com/api/github/setup` (with Redirect on update on) and the webhook URL `https://dirt.example.com/api/github/webhook` with a random secret. It needs Deployments read and write, Pull requests read and Metadata read, and the Pull request event.
2. Generate a private key and a client secret.
3. Set `GITHUB_APP_ID`, `GITHUB_APP_SLUG` (from `github.com/apps/<slug>`) and `GITHUB_APP_CLIENT_ID`, and the secrets `GITHUB_APP_PRIVATE_KEY` (the `.pem` as GitHub gives it), `GITHUB_APP_CLIENT_SECRET` and `GITHUB_APP_WEBHOOK_SECRET`. On GitHub Enterprise Server, also `GITHUB_API_URL` and `GITHUB_WEB_URL`.
4. An org owner links the org from a pipe's card on the wall, under Pull request, Connect GitHub.

## Limits

| Var                     | Default | What it limits, per org               |
| ----------------------- | ------- | ------------------------------------- |
| `LIMIT_ACTIVE_SHARES`   | 5       | Pipes open at once                    |
| `LIMIT_MONTHLY_BYTES`   | 100 GB  | Traffic a month                       |
| `LIMIT_SHARE_SECONDS`   | 12 h    | The longest `--ttl`                   |
| `DEFAULT_SHARE_SECONDS` | 4 h     | A pipe's lifetime when it doesn't ask |

`RATE_LIMIT_AUTH`, `RATE_LIMIT_MAGIC_LINK`, `RATE_LIMIT_CONNECT`, `RATE_LIMIT_MANAGE` and `RATE_LIMIT_MCP` take `<count>/<seconds>`, or `off`.

## Hosted MCP server

On by default, with nothing to set up. People add `https://api.example.com/mcp` (your `CONNECT_HOST`, or `BETTER_AUTH_URL`'s host without one) to their assistant and sign in through dirt. The access tokens are signed with a key Wurmhol creates in D1 on first use, encrypted with `BETTER_AUTH_SECRET`.

- `MCP_ENABLED=false` turns it off: `/mcp` and its sign-in routes answer 404.
- `RATE_LIMIT_MCP`, 120 calls a minute per person or token by default.
- Assistants register by Client ID Metadata Document: the Worker fetches the HTTPS URL the assistant names as its client id, at most 64 KB, without following redirects.
- It needs HTTPS, or plain HTTP on `localhost` or `127.0.0.1`. A stack on plain HTTP under any other host, like `api.localhost`, has it off.

## Takedown

When someone reports a pipe for phishing or abuse, you take it down with one call. Set `OPERATOR_TOKEN` first, a secret of at least 32 random characters (`openssl rand -base64 32`, then `wrangler secret put OPERATOR_TOKEN`). Without it, `/operator/*` answers 404.

```bash
curl -X POST https://dirt.example.com/operator/takedown \
  -H "Authorization: Bearer $OPERATOR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"pipe": "https://k3x9m2p7qa.example-pipes.dev/login"}'
```

- `pipe` is the reported URL, its host, the pipe's id, or a named pipe's name.
- The pipe ends now, the token that opened it is revoked, and that token's other pipes and machines end with it. Each CLI prints why and stops.
- `"blockOrg": true` also blocks the org: every pipe of it ends, and none of its tokens, old or new, opens another. Add a `"note"` with the report it answers.
- The answer lists the revoked token's id and every pipe that ended.
- To unblock an org: `wrangler d1 execute wurmhol --remote --command "delete from org_blocks where org_id = '<org id>'"`.

## Docs link

The wall's Docs links go to `https://wurmhol.com/docs`. Set `DOCS_URL` to send them to your own docs instead.

## Cleanup

Once a day the Worker deletes pipe history older than `RETENTION_DAYS` (90), plus expired sessions, sign-in links, invite links and device logins. `wrangler deploy` sets that up. It only writes its own log lines, Cloudflare's invocation logs are off so request URLs aren't recorded. Every var is in [`apps/worker/.dev.vars.example`](https://github.com/handlemotion/wurmhol/blob/main/apps/worker/.dev.vars.example).
