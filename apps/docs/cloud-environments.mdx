## Claude Code cloud environments

The console shows these values after you create a token, each copied in one click. In the
environment's settings:

- Under **Environment variables**, add `WURMHOL_TOKEN=wh_…`.
- Under **Network access → Allowed domains**, add `api.wurmhol.com`. It is the only host the CLI
  dials; viewers open pipes in their own browsers.

New sessions pick them up. A token stored by `wurmhol login` dies with the container, so use
`WURMHOL_TOKEN` in sandboxes. It wins when both are there.

## Teach your agent

In Claude Code, the `wurmhol` plugin teaches the agent when to share, how, and to keep the token
out of its output:

```text
/plugin marketplace add handlemotion/wurmhol
/plugin install wurmhol@wurmhol
```

For any other agent, run this in the project:

```bash
npx wurmhol init
```

It appends one line to `AGENTS.md` (or `CLAUDE.md` if that is the file you have) with the dev
server's port, read from `package.json`: Next 3000, Astro 4321, Vite 5173, anything else 8787.
`--skill` also writes the skill to `.claude/skills/wurmhol/SKILL.md`.

## Proxies

The CLI dials through `HTTPS_PROXY` when it is set, and trusts the proxy's CA from
`NODE_EXTRA_CA_CERTS`. It needs Node 22 or later.
