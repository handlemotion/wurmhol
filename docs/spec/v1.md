# Wurmhol v1 spec

Wurmhol gives a coding agent's dev server a private HTTPS URL that its humans open in their own
browser, from inside sandboxed cloud containers (Claude Code cloud and similar) where ngrok and
Cloudflare Tunnel can't connect.

- Product: Wurmhol, wurmhol.com
- Repo: handlemotion/wurmhole
- CLI on npm: `wurmhol` (check the name is free)
- Owner: Handlemotion. Built the way Omni (handlemotion/omni) is built, reusing its code where
  this spec says so.

## 1. Problem

Agents in cloud sandboxes build web apps their humans can't open. Those containers reach the
internet only through an HTTPS CONNECT proxy on port 443, which terminates TLS with its own CA.
They have no DNS and no other ports. Tested from a Claude Code cloud session on 2026-11-05:

| Tool                    | Result from the sandbox                                                  |
| ----------------------- | ------------------------------------------------------------------------ |
| Cloudflare quick tunnel | Gets a URL, never connects: no DNS for argotunnel.com, port 7844 closed  |
| ngrok                   | Fails the same way                                                       |
| Microsoft devtunnel     | Works, but needs an interactive login every session                      |
| Tailscale               | Works (Omni's `pnpm share`), but every viewer needs a tailnet and the app |
| Claude preview pane     | Not your browser: no extensions, no phone, nothing to share              |

Goal: the agent runs one command and sends a link. You tap it and use the app in your own
browser, on any device. Nobody outside your org can open it.

## 2. Product

```bash
npx wurmhol 8787
```

It prints `https://k3x9p2.on.wurmhol.com`, which opens only for members of the org that owns
the token.

Promises:
- One command, one URL, in under 3 s once a token is set.
- Works through an HTTPS-only egress proxy: one outbound WebSocket on 443, nothing else.
- Private: viewers sign in, and only members of the token's org get through.
- A new URL for every share, dead when the share ends.
- Nothing to install on the viewing device.

Not in v1: public links, custom domains, TCP/UDP tunnels, production hosting, per-share
invites.

## 3. The app

The whole app is a login page and one main page.

### Login page
Same Better Auth sign-in as Omni (`packages/auth`): passkeys, plus Google and GitHub OAuth.
Magic links come once a mail sender exists (open question 4). Self-serve sign-up creates a
personal org.

### Main page: the shares wall (Are.na style)
- A grid of plain, minimal cards: thin border, no shadow, generous whitespace, the same size
  everywhere. On a phone, one column.
- One card per open share in the current org:
  - Title: the page's `<title>`, taken from the last HTML response the relay saw. Fallback: the
    hostname.
  - Favicon, when the dev server serves one.
  - A small, quiet line: port, who started it, how long ago, time of the last request.
- Clicking the card opens the share URL in a new tab.
- A small Terminate button in the card's corner (`Button intent="danger" size="sm"`, labelled
  "Terminate"). It ends the share at once and closes the CLI's socket.
- Empty state: one line plus the command, in a `CopyField`: `npx wurmhol <port>`.
- Live: cards appear and disappear as shares start and end (WebSocket from the org's Durable
  Object; no polling).

### Header menu (the only other UI)
An org switcher plus a menu. Every item leads with a Lucide icon, per DESIGN.md:
- **Members**: a dialog. List members, invite by copyable link (`CopyField`), remove. Roles are
  owner and member.
- **Tokens**: a dialog. Create a token (shown once, in a `CopyField`), list tokens by name and
  last use, revoke.
- **Billing**: opens the Stripe customer portal, or Checkout when there's no subscription.
- **Log out**.

### Design system
Copy from Omni rather than rebuilding:
- `apps/web/src/styles.css` (tokens)
- `components/ui` primitives (Intent UI on React Aria and Tailwind)
- `components/icons`
- DESIGN.md and its rules: components only, semantic classes, `skullet` for loading states
- the `design-balance` skill

Trim whatever Wurmhol doesn't use. Keep light and dark themes.

## 4. Orgs, auth and billing (copied from Omni)

- **Better Auth** with the organization, passkey, multi-session and Stripe plugins, the same
  setup as Omni's `packages/auth`. Session cookies are `__Host-` cookies on wurmhol.com.
- **Org model:** a person belongs to one or more orgs. Tokens, shares and the subscription all
  belong to an org. Every member of an org can open and terminate any of its shares.
- **Stripe billing**, through the Better Auth Stripe plugin, billed to the org (like Omni's
  ADR 0015):
  - One plan: $3 a month or $30 a year. Push yearly: at US card rates a $3 monthly charge loses
    about 13% to fees, a yearly charge about 4%.
  - Stripe Checkout to start, the customer portal to manage, webhooks to sync.
  - Without a subscription: a 7-day trial, then shares refuse to start until the org subscribes
    (open question 5).
- **Fair-use limits per org** (enforced in the Durable Objects): 5 active shares, 100 GB a month,
  12-hour maximum per share. Measure real cost in the beta before fixing these.

## 5. Architecture

Everything runs in one Cloudflare Worker, with Durable Objects and D1.

```
viewer browser --HTTPS--> Worker (*.on.wurmhol.com) --> Share DO <==WebSocket== CLI --> 127.0.0.1:<port>
                              |                                    (dialed out through
                              +--> wurmhol.com: login + shares wall      the sandbox proxy)
```

| Part         | Runs on                    | Job                                                                                                                              |
| ------------ | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| CLI          | the sandbox, Node 20+      | Dials `wss://wurmhol.com/connect` through `HTTPS_PROXY`, trusts `NODE_EXTRA_CA_CERTS`, forwards each request to `127.0.0.1:<port>` |
| Worker       | Cloudflare                 | Hono API, auth, Stripe webhooks, serves the SPA, routes `*.on.wurmhol.com` to the share's DO                                     |
| Share DO     | one per share              | Holds the CLI socket (hibernation API), multiplexes requests, records title and last request, enforces limits                    |
| Org DO       | one per org                | Live list of the org's shares for the wall; counts toward limits                                                                 |
| D1 + Drizzle | Cloudflare                 | Users, orgs, members, tokens (hashed), subscriptions, share history                                                              |

D1 instead of Omni's PlanetScale and Hyperdrive: it's cheaper, there's one less vendor, and
self-hosting needs only a Cloudflare account. Better Auth runs on D1 through Drizzle's SQLite
adapter. Record this as ADR 0001.

### Wire protocol (`packages/protocol`, pure, unit-tested)
- One WebSocket carries many streams. A frame is `{stream, type, payload}`.
- Types: `request`, `response`, `data`, `end`, `ws-open`, `ws-message`, `ws-close`, `ping`.
- Bodies stream in chunks of up to 64 KB, so large assets and server-sent events work.
- A browser WebSocket (Vite hot reload) is its own stream.
- The CLI sends a heartbeat every 20 s. On reconnect it keeps the same share id for up to 60 s.

### Domains
- `wurmhol.com`: the app, the API and `/connect`.
- `<id>.on.wurmhol.com`: shares.
- Submit `on.wurmhol.com` to the Public Suffix List on day one. That makes each share its own
  site, so one share's JavaScript can't read or plant cookies for another share or the app.
- Two-level wildcard TLS needs Cloudflare Advanced Certificate Manager ($10 a month).

## 6. Security model

- **Viewer sign-in:**
  1. An unknown viewer on a share is redirected to `wurmhol.com/open?share=<id>`.
  2. After sign-in and a membership check, the app redirects back with a one-time code (60 s,
     single use).
  3. The Worker swaps the code for a `__Host-wurmhol` cookie on that share host: HttpOnly,
     Secure, SameSite=Lax, 12 hours.
  4. The Worker strips that cookie before forwarding, so the dev server never sees it.
- **Tokens:** random, at least 32 bytes, stored hashed, scoped to "start shares for this org",
  revocable. Share ids: random, 10 characters, never reused.

| Threat                                 | Mitigation                                                       |
| -------------------------------------- | ---------------------------------------------------------------- |
| URL found or guessed                   | Sign-in and membership check on every request                    |
| Token leaked                           | Shares stay org-only; revoke in one click; the wall shows every share |
| Dev app's JavaScript attacks others    | Public Suffix List entry, `__Host-` cookies, app on another host |
| Phishing hosted on shares              | Only signed-in org members see pages; takedown path              |
| Used as a free proxy or file host      | Limits; no unauthenticated traffic                               |
| Relay can read traffic                 | Stated plainly; request bodies are never logged                  |

## 7. CLI and agent ergonomics

- `npx wurmhol <port>` detaches and returns once the share answers. It prints the bare URL as
  its first stdout line; `--json` prints `{url, port, id}`.
- `wurmhol ls`, `wurmhol stop <port|id>`, `wurmhol stop --all`.
- Port not listening yet: the share starts anyway and the page says "Waiting for the server on
  port 8787".
- Forwards `Host: localhost:<port>` so Vite and most frameworks need no config. Sets
  `X-Forwarded-Host` and `X-Forwarded-Proto` for apps that build absolute URLs.
- Errors say the fix in one line: token missing or revoked, port refused, proxy denied host
  (naming the hosts to allowlist: `wurmhol.com`, `*.on.wurmhol.com`), no subscription.
- `WURMHOL_TOKEN` from the environment. `WURMHOL_URL` points at a self-hosted install.
- `wurmhol init` appends one line to AGENTS.md or CLAUDE.md: "Share a local server with
  `npx wurmhol <port>` and send the user the URL."
- Later: an MCP server with `share_port`, `list_shares` and `stop_share`.

## 8. Repo, tooling and operations (mirror Omni)

Layout: pnpm workspaces plus Turborepo, TypeScript, Node 26 (`.nvmrc`).

| Unit                | Package             | Role                                                                              |
| ------------------- | ------------------- | --------------------------------------------------------------------------------- |
| `apps/worker`       | `@wurmhol/worker`   | The Worker: Hono API, auth, Stripe, relay routing, DOs; serves `apps/web`         |
| `apps/web`          | `@wurmhol/web`      | Vite SPA: login and the shares wall                                               |
| `packages/cli`      | `wurmhol` (npm)     | The CLI                                                                           |
| `packages/protocol` | `@wurmhol/protocol` | Frame codec and stream multiplexer. Pure, no I/O                                  |
| `packages/auth`     | `@wurmhol/auth`     | Better Auth config (from Omni)                                                    |
| `packages/db`       | `@wurmhol/db`       | Drizzle schema and D1 migrations                                                  |

Copy from Omni and adapt:
- `AGENTS.md` and `CLAUDE.md` (same rules: E2E first, Doppler, self-hostable, PR writing,
  stacks)
- `DESIGN.md` and the `.claude/skills` folder (`pr-writing`, `design-balance`, `gh-stack`)
- `lefthook.yml`, `lint-staged`, `oxfmt`, `oxlint`
- `scripts/check-tests.mjs`, `scripts/check-workflows.mjs`
- `.claude/hooks/cloud-session-start.sh` and `kickoff.sh`
- `scripts/serve.mjs` (`pnpm stack:serve`)
- `SECURITY.md` and `LICENSE` (see section 9)

**Secrets: Doppler project `wurmhol`.**

| Config       | Consumer                         | Holds                                                                                                    |
| ------------ | -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `dev`        | every local command              | local D1 settings, non-secret dev config                                                                 |
| `dev_worker` | `wrangler dev` (mounted `.dev.vars`) | `BETTER_AUTH_SECRET`, OAuth client secrets, Stripe sandbox keys (`STRIPE_*`)                         |
| `prd_worker` | Worker secrets                   | `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` |
| `prd_github` | `production.yml`                 | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `NPM_TOKEN`, records (`WORKER_VAR_*`)                    |

- Same rules as Omni's `docs/operations/doppler.md`: a key is a secret or a var, never both;
  check by name only; headless via `DOPPLER_TOKEN`.
- Cloud sessions get read-only service tokens in environment variables (`DOPPLER_TOKEN`,
  `DOPPLER_TOKEN_WORKER`), and the session hook writes local env files from them.

**Deploys (Omni ADR 0019):**
- Cloudflare Workers Builds deploys `main`.
- `.github/workflows/production.yml`, on each push to `main` and by hand:
  1. `wrangler d1 migrations apply` (additive-first schema, as in Omni).
  2. Waits for the commit's Workers Builds check, then syncs `prd_worker` to Worker secrets with
     `wrangler secret bulk`.
  3. Publishes `packages/cli` to npm when its version changes (npm provenance on).
- Never deploy from a laptop.

**CI** (`main` ruleset: green `Checks`, squash merge):
- `ci.yml` "Checks": `pnpm check` (format, lint, policies), `pnpm check-types`, unit tests,
  E2E tests.
- `codeql.yml`, `gitleaks.yml`, `dependency-review.yml`.
- **Unit tests** only for `packages/protocol` (frame round-trips, chunking, stream interleaving)
  and `scripts/`.
- **E2E** against the real stack (`wrangler dev` with local D1 and DOs, the real CLI, a real
  local HTTP server), with no mocks. They cover:
  - a share round-trip
  - a 50 MB body
  - an SSE stream
  - Vite hot reload over the WebSocket
  - a signed-out viewer refused
  - another org's member refused
  - terminate from the wall
  - a revoked token
  - limits

**Self-hosting:** one Cloudflare account, two hostnames, `wrangler deploy`, and the env vars
documented in `.dev.vars.example`. Steps go in `docs/self-hosting.md`. No Handlemotion values in
code.

## 9. License

Decide before the first public commit (open question 1). Recommendation, matching Omni:
- App (`apps/*`, `packages/{auth,db,protocol}`): AGPL-3.0. Hosted wurmhol.com is the product.
- CLI (`packages/cli`): MIT. It ships to npm anyway, and agent tools can bundle it freely.

If closed source instead: keep the repo private and the CLI MIT, published from the same repo.

## 10. Milestones

1. **Prototype.** CLI, relay and DOs. A single hard-coded org, no billing. Used daily from
   Omni's cloud sessions instead of `pnpm share`.
   - Gate: the Omni stack works through it, including sign-in and realtime updates.
2. **Private beta.** Login, orgs, tokens, the shares wall, terminate, and the Public Suffix List
   entry submitted.
   - Gate: the v1 acceptance list passes.
3. **Launch.** Stripe billing, limits, `npx wurmhol` on npm, docs, a landing page on
   wurmhol.com.

### v1 acceptance
Run from a fresh Claude Code cloud session, with the viewer on a phone over cellular data:
- [ ] `npx wurmhol 8787` prints a URL within 3 s, with `WURMHOL_TOKEN` set.
- [ ] Omni works through it: magic-link sign-in, the inbox loads, realtime updates arrive.
- [ ] Vite hot reload works on `npx wurmhol 5173` with no Vite config change.
- [ ] A 50 MB download and a 10-minute SSE stream pass through intact.
- [ ] A signed-out browser and a member of another org both get the login page, never the app.
- [ ] The wall shows the share within 2 s of it starting, with the page title.
- [ ] Terminate ends the share within 5 s; the URL then says the share ended.
- [ ] Stripe Checkout, a webhook-driven plan change and the customer portal all work in test
      mode.
- [ ] A self-hosted copy on a second Cloudflare account passes the same list.

## 11. Risks

| Risk                                                 | Response                                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| Agent hosts ship native share links                  | Ship small and fast; stay host-neutral (Claude Code, Codex, Cursor, any sandbox) |
| Users must allowlist our hosts in Limited network mode | Name both hosts in every error; ask Anthropic to add them by default later    |
| Public Suffix List review takes weeks                | Submit on day one; it isn't needed until the beta                              |
| Abuse gets the domain flagged                        | No public links in v1; limits; a fast takedown path                            |
| The proxy cuts long WebSockets                       | 20 s heartbeat; reconnect keeps the share id                                   |
